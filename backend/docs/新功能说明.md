# SRM系统 - 新功能说明

## 🎉 本次更新内容

### 1. 公司（分公司）管理模块 ✅

**功能说明：**
- 管理集团下的各个分公司信息
- 项目可关联到具体的分公司
- 供应商项目历史可追踪参与过哪些分公司的项目

**数据库表：`companies`**
```sql
- id: 主键
- company_code: 公司编码（唯一）
- company_name: 公司名称（唯一）
- company_type: 公司类型（总部/分公司/子公司）
- legal_person: 法人代表
- registered_capital: 注册资本
- business_license: 营业执照号
- contact_person: 联系人
- contact_phone: 联系电话
- contact_email: 联系邮箱
- province/city/district/address: 地址信息
- description: 公司描述
- is_active: 是否启用
- sort_order: 排序
```

**API接口：`/api/v1/companies`**
- `GET /` - 获取公司列表
- `GET /{id}` - 获取公司详情
- `POST /` - 创建公司
- `PUT /{id}` - 更新公司
- `DELETE /{id}` - 删除公司

**默认数据：**
- 集团总部（HQ）
- 北京分公司（BJ01）
- 上海分公司（SH01）

### 2. 品牌管理模块 ✅

**功能说明：**
- 统一管理所有品牌信息
- 报价时可选择已有品牌或手动输入
- 便于品牌数据的规范化和统计

**数据库表：`brands`**
```sql
- id: 主键
- brand_code: 品牌编码（唯一）
- brand_name: 品牌名称（唯一）
- brand_name_en: 品牌英文名
- category: 品牌类别
- origin_country: 原产国
- manufacturer: 生产厂家
- official_website: 官方网站
- contact_phone: 联系电话
- contact_email: 联系邮箱
- logo_url: 品牌Logo
- description: 品牌描述
- is_active: 是否启用
- is_recommended: 是否推荐
- sort_order: 排序
```

**API接口：`/api/v1/brands`**
- `GET /` - 获取品牌列表（可按类别筛选）
- `GET /{id}` - 获取品牌详情
- `POST /` - 创建品牌
- `PUT /{id}` - 更新品牌
- `DELETE /{id}` - 删除品牌

**默认数据：**
- 联想（LENOVO） - 电子产品
- 华为（HUAWEI） - 电子产品
- 海螺水泥（HA螺） - 建筑材料

### 3. 供应商项目参与历史 ✅

**功能说明：**
- 记录供应商参与过的所有项目
- 自动记录报价、中标情况
- 支持对供应商的项目表现进行评分
- 便于后续选择供应商时参考历史记录

**数据库表：`supplier_project_history`**
```sql
- id: 主键
- supplier_id: 供应商ID
- project_id: 项目ID
- company_id: 所属公司ID（哪个分公司的项目）
- participated_at: 参与时间
- is_winner: 是否中标（0-未中标，1-中标）
- contract_amount: 合同金额
- quality_score: 质量评分（1-5）
- service_score: 服务评分（1-5）
- delivery_score: 交付评分（1-5）
- overall_rating: 综合评价（优秀/良好/一般/差）
- remarks: 备注说明
```

**自动记录时机：**
1. 供应商提交报价时 → 自动创建参与历史记录
2. 报价被评审为中标时 → 自动更新 `is_winner=1`
3. 项目完成后 → 可由项目经理补充评分和评价

### 4. 数据关联优化 ✅

#### 4.1 项目关联公司
**变更：**
- 项目表新增 `company_id` 字段
- 关联到 `companies` 表
- 原有的 `branch_office` 字段保留作为备用

**用途：**
- 明确项目属于哪个分公司
- 统计各分公司的项目数量
- 供应商可查看参与过哪些分公司的项目

#### 4.2 报价明细关联品牌
**变更：**
- 报价明细表新增 `brand_id` 字段
- 关联到 `brands` 表
- 原有的 `brand` 字段保留作为备用（手动输入）

**用途：**
- 规范品牌数据
- 品牌数据统计分析
- 提供品牌下拉选择

## 💡 业务场景示例

### 场景1：项目经理创建项目并关联分公司

```bash
POST /api/v1/projects/
{
  "project_name": "2025年办公设备采购",
  "company_id": 2,  // 关联到"北京分公司"
  "branch_office": "北京分公司",  // 备用字段
  "items": [...]
}
```

### 场景2：供应商报价时选择品牌

```bash
POST /api/v1/quotations/
{
  "project_id": 1,
  "items": [
    {
      "project_item_id": 1,
      "unit_price": 3800,
      "quantity": 50,
      "brand_id": 1,  // 选择"联想"品牌
      "brand": "联想",  // 备用字段
      "model": "启天M428"
    }
  ]
}
```

### 场景3：查询供应商的项目参与历史

```bash
GET /api/v1/suppliers/{supplier_id}/history
```

返回该供应商参与过的所有项目：
- 哪些分公司的项目
- 是否中标
- 历史评分
- 综合评价

## ⚠️ 重要提示

### 数据迁移说明

如果您已经有旧数据，需要注意：
1. `projects` 表新增了 `company_id` 字段
2. `quotation_items` 表新增了 `brand_id` 字段
3. 新增了3个表：`companies`、`brands`、`supplier_project_history`

**建议操作：**
```bash
# 1. 备份现有数据（如果有）
mysqldump -u root -p srm > srm_backup.sql

# 2. 重置数据库
reset_db.bat

# 3. 或者使用Alembic进行数据库迁移（推荐生产环境）
alembic revision --autogenerate -m "add companies and brands"
alembic upgrade head
```

### 字段兼容性

为了保持兼容性，我们保留了原有字段：
- `projects.branch_office` - 如果 `company_id` 为空，会使用此字段
- `quotation_items.brand` - 如果 `brand_id` 为空，会使用此字段

这样即使不选择品牌或公司，也可以手动输入。
