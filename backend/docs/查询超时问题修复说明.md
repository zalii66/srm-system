# 查询超时问题修复说明

## 🔴 问题

数据库查询优化后，出现查询超时（30秒超时）。

## 🔍 根本原因

**过度预加载导致性能问题**

1. **嵌套 `selectinload` 导致多次查询**
   - `selectinload(User.roles).selectinload(Role.permissions)` 
   - 会执行多个 SELECT 查询，当数据量大时性能下降

2. **列表查询不需要加载权限**
   - 权限通常在权限检查时才需要
   - 列表查询只需要角色信息即可
   - 每次都加载权限会导致不必要的查询

3. **`get_current_user` 每次请求都执行**
   - 如果查询太慢，会影响所有需要认证的请求

## ✅ 优化策略

### 1. 按需加载权限

**原则：**
- 列表查询：只加载角色，不加载权限
- 详情查询：只加载角色，权限按需加载
- 权限检查：需要时才加载权限

### 2. 优化 UserService

**修复前：**
```python
# 每次都加载角色和权限
selectinload(User.roles).selectinload(Role.permissions)
```

**修复后：**
```python
# 只加载角色，权限按需加载
selectinload(User.roles)
```

### 3. 优化 get_current_user

**修复前：**
```python
# 每次登录都加载所有权限
user = db.query(User).options(
    selectinload(User.roles).selectinload(Role.permissions)
).filter(User.username == token_data.sub).first()
```

**修复后：**
```python
# 只加载角色，权限按需加载
user = db.query(User).options(
    selectinload(User.roles)
).filter(User.username == token_data.sub).first()
```

## 📝 修改的文件

1. ✅ `backend/app/services/user_service.py`
   - 所有查询方法：只加载角色
   - `get_multi()`：明确注释不加载权限以提高性能

2. ✅ `backend/app/core/deps.py`
   - `get_current_user()`：只加载角色

## 🎯 性能优化效果

### 查询次数对比

**修复前（嵌套 selectinload）：**
```
1. SELECT users (主查询)
2. SELECT roles WHERE user_id IN (...)
3. SELECT role_permission WHERE role_id IN (...)
4. SELECT permissions WHERE permission_id IN (...)
```
**总查询数：4 次**

**修复后（只加载角色）：**
```
1. SELECT users (主查询)
2. SELECT roles WHERE user_id IN (...)
```
**总查询数：2 次**

### 性能提升

- **查询次数减少：** 50%
- **响应时间：** 预计减少 40-60%
- **数据库负载：** 显著降低

## ⚠️ 注意事项

### 权限检查

如果代码中需要检查权限，可以：

1. **按需加载权限：**
   ```python
   # 需要权限时再加载
   for role in user.roles:
       # 触发权限加载（如果还没加载）
       permissions = role.permissions
   ```

2. **使用角色代码检查：**
   ```python
   # 大多数权限检查只需要角色代码
   is_project_manager = any(role.code == "project_manager" for role in user.roles)
   ```

3. **专门的权限查询：**
   ```python
   # 如果需要完整权限列表，可以单独查询
   role = db.query(Role).options(
       selectinload(Role.permissions)
   ).filter(Role.code == "supplier").first()
   ```
