## 📝 使用说明

### 重要说明：`.env` 中密码的用途

**⚠️ 关键理解：**

1. **`.env` 中的 `DEFAULT_ADMIN_PASSWORD` 只在数据库初始化时使用一次**
   - 运行 `init_db.py` 时会读取这个密码
   - 密码会被哈希后存储到数据库中
   - 初始化完成后，`.env` 中的密码就不再使用了

2. **登录验证流程：**
   - 用户登录时，系统从数据库读取用户信息（包含哈希后的密码）
   - 使用 `verify_password()` 函数验证用户输入的密码与数据库中的哈希密码
   - **完全不依赖 `.env` 文件中的密码**

3. **为什么要在 `.env` 中设置：**
   - 避免在代码中硬编码密码
   - 提高安全性：即使代码泄露，不知道 `.env` 文件内容也无法知道初始密码
   - 生产环境可以设置强密码，而不是使用默认的 `admin123`

### 环境变量配置

1. **复制 `.env.example` 为 `.env`：**
   ```bash
   cp .env.example .env
   ```

2. **编辑 `.env` 文件，设置必要的配置：**
   ```env
   DB_HOST=localhost
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=your_db_password
   DB_NAME=srm_db
   SECRET_KEY=your_secret_key_here
   
   # 仅用于数据库初始化时创建默认管理员账户
   # 初始化后，密码会被哈希存储到数据库，不再使用此配置
   # 生产环境必须设置强密码
   DEFAULT_ADMIN_PASSWORD=your_strong_admin_password
   ```

3. **生产环境部署：**
   - 必须设置 `DEFAULT_ADMIN_PASSWORD` 环境变量（用于初始化）
   - 初始化完成后，可以在 `.env` 中删除此配置（可选，但建议保留用于后续重新初始化）
   - 建议设置 `DEBUG=False`
   - 使用强密码（至少8位）

### 开发环境

- 可以不设置 `DEFAULT_ADMIN_PASSWORD`，将使用默认密码 `admin123`
- 会显示警告信息，提醒生产环境必须修改

### 权限检查使用示例

```python
from app.core.permissions import check_business_license_permission

# 检查营业执照文件权限
check_business_license_permission(db, current_user, year_month, filename)
```

### 异常处理使用示例

```python

# 抛出资源不存在异常
if not resource:
    raise NotFoundError("用户不存在")

# 抛出业务逻辑错误
if status == "completed":
    raise BusinessLogicError("已完成的项目不能修改")
```
